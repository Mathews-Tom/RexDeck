# Changelog

## 0.2.1 — 2026-11-09

- `rexdeck plugins` and `rexdeck status` print a readable table at a terminal: one row per plugin with state, tool/versions and pane layout, then a **Needs attention** section that gives each problem and its fix once (shared causes such as Rex missing from `PATH` are not repeated per plugin). Server URLs are shown decoded; remote/receipt text is stripped of terminal control characters; state color follows `NO_COLOR`/`TERM=dumb`. `--json`, or piped output, keeps the full JSON document unchanged; exit codes are unchanged.
- The ClickUp capability disclosure now lists the description and sprint-points writes added in 0.2.0.

## 0.2.0 — 2026-11-09

New integrations: Markdown, Usage, GitHub, Viewer, ClickUp, native attention and opt-in Claude Code/Codex subagent hooks, plus configurable pane placement and size for every integration. Upgrading from 0.1.x: run `rexdeck enable <id>` for each previously enabled integration (Files, Git) to refresh its native module.

- Published the approved main-CI wheel/sdist (commit `32bcb43`, artifact `13638546210`) to GitHub and PyPI from tag `v0.2.0`; public asset and registry hashes match. A no-cache public-index install listed every integration and ran the ClickUp native action in a private Rex with exact-origin quit and clean disable.

- ClickUp: propose and confirm `description MARKDOWN` (replaces the whole description through `markdown_content`, staged against the current Markdown) and `points NUMBER` (native Sprint Points; negative/non-numeric/non-finite values refused before any request, and ClickUp itself refuses values off the workspace's point scale). Task detail shows `points=`. The engine's `touch` gains `--description` and `--points`. HTTP 400 is now a coded `request/rejected` finding (pane state `REJECTED`, keeping only ClickUp's short `ECODE`) instead of a malformed response, and a refused write says it was not applied rather than "may have succeeded".
- README: Linear is listed as not implemented (help wanted) and an untested-environments section names GitHub Enterprise/multi-account and second-account ClickUp as unqualified, inviting issues and PRs.
- Add independently selectable ClickUp through an owned pane/MIT engine: explicit identity, multipage reads, native statuses, custom IDs, comments/replies, filter/search/sprint and validated links. Writes require nonce-bound proposal confirmation and independent concurrency digests; approval is rechecked after pacing, refresh is refused while writing, and no hidden retries occur. Explicit registry selection/sync, private caches, credential-free browser environments and safe text rendering. No workspace registry is committed.
- Filter the launched upstream tool's `PATH` to absolute entries, matching dependency discovery, so a selected working directory is not implicitly searched for helpers. Disclose Viewer's sibling-file preloading and helper licenses; document source paging without LESSOPEN preprocessing.
- Add opt-in, silent, fail-open `attention hook claude-code|codex` receivers for documented subagent start/stop metadata and exact provider-reported parentage. Retain IDs/type/cwd, receipt time, presence-only message/transcript flags and inherited verified Rex binding; never read transcripts or retain their paths/message content. Integrate exact provider/parent/agent filters and parent groups with local freshness and D10's revalidated jump; unbound targets cannot focus. Preserve native schema 1 and its 256-row/2 MiB capacity with a separate hardened 64-row/256 KiB provider store. Accept up to 2 MiB stdin JSON and drain oversized input within the receiver deadline; use remaining deadline budget for contended locks. Add scoped provider-row clearing and exact owner-only hook configuration/trust/rollback docs, including Claude internal-agent/matcher, async-timeout and first-real-run identity caveats. Script proof only; real provider events await owner hook installation and one real subagent per provider. omp lacks the required public interactive lifecycle hook.
- Isolate damaged provider evidence in attention listing/clearing: retain healthy native rows with structured provider faults and document deliberate provider-only recovery. Release provider jump locks before Rex IPC so hooks can continue recording during navigation; distinguish absent versus explicitly empty Rex endpoint bindings.
- Bound contended provider reads, validate stored row keys, keep hook deadlines active through endpoint validation and native subprocess cleanup, and invalidate any binding captured at a timeout boundary. Use a persisted pre-lookup receipt sequence rather than wall-clock time for concurrent lifecycle ordering, and keep deadline cleanup inside the silent fail-open hook boundary.
- `status` and `plugins` report `missing-dependency` (nonzero exit) when an enabled integration's upstream tool is no longer on `PATH`, instead of a generic `fault`. The README documents every integration state and how to install an exact public source commit for integrations merged after the latest release.
- Add the independently selectable Usage integration: `rexdeck enable usage` runs unmodified tokscale 4.21.0 as `tokscale tui --client omp` in a native pane. It keeps tokscale's normal online pricing/refresh and its `r` manual refresh and `Shift+R` auto-refresh; RexDeck never forces `--offline`, passes `--refresh`, or invokes login, submit, autosubmit or report. Usage is machine-wide, not a project filter, and the README discloses tokscale's network, provider-credential and account-control behaviour.
- Add independently selectable GitHub workflows through unmodified gh-dash 4.26.2, with explicit `account=LOGIN`, `repo=HOST/OWNER/REPO` or `remote=NAME`; refuse repository-less/ambiguous contexts, verify existing auth/account and repository accessibility without credential copying or global account switching, and preserve exact-origin return plus local Git's independent behavior. Temporary repository-scoped section overlays retain upstream theme, keybindings and commands, including the invoking directory's `.gh-dash.yml`/`.gh-dash.yaml` or `GH_DASH_CONFIG`, while replacing custom section lists and initial view; overlays are cleaned up on SIGHUP/SIGTERM as well as normal exit. The upstream UI is disclosed as write-capable.
- Add native `rexdeck attention observe/list/jump`: bounded, explicit per-terminal OSC 7501/exit observations retained with source, timestamps, project/location filters and bound/unbound/closed/disconnected distinctions. Navigation revalidates the saved endpoint, server instance and exact placed session/block without fallback. No hooks, watcher, transcript ingestion, provider identity inference or process control; durable agent-session identities and provider-specific parentage remain outside this native terminal view. Retention uses no-follow/nonblocking regular-file opens, private locks, file/directory fsync, finite timestamps, authoritative row IDs and bounded/truncation-marked terminal fields (16 KiB per row). Add explicit `attention observe <observation-id>` refresh, carry the newest exact-binding project label across incarnations, preserve observed placement on closure, and invalidate every older-instance endpoint row on restart.
- Add independently selectable `viewer`: a required explicit local PDF/JPG/PNG/SVG selection opens unmodified Yazi 26.9.1 using Rex Kitty graphics, with PDF page navigation through pdftoppm and static SVG rasterization through resvg. Missing selections, unsupported targets and obvious format mismatches fail before a pane opens. Document per-format runtime evidence, source viewing, helper requirements, graphics/GUI observation limits and the unrestricted upstream-tool/untrusted-file boundary; no automatic native-browser handoff or RexDeck renderer is added.
- Add the independently selectable Markdown integration: `rexdeck enable markdown` hosts unmodified markdown-reader 1.35.4, which draws Mermaid as Unicode text diagrams inside the Rex pane, alongside rendered prose, tables and code. The palette action browses the invoking directory, and the action's `file` argument (absolute, `file://` or relative to the invoking terminal) opens a selected `.md`/`.markdown` file. Invalid selections fail before a pane opens. The shared host gains a `document` context, which passes the validated target to the tool as its final argument.
- Add configurable pane placement and size: `rexdeck enable <id> --placement {right,left,below,above} --size 20-80`. Invalid values are rejected before any change; omitted options keep the integration's saved layout across refresh and disable/enable; status and listings report it. Layout is stored in each integration's own receipt (still schema 3; receipts without a layout keep the original right/50% split), so changing Git's layout leaves Files untouched.
- Consolidate Files and Git onto one shared native host contract: `rexdeck.integrations` descriptors declare identity, qualified versions, license, launch context, shell-less argv, default layout and capability disclosure; the shared `host/main.lua` action and `host/launch.py` launcher replace the Files/Git branches, and lifecycle ownership handles any number of sibling loaders. Loader bytes, deployment paths, settings schema 2 and receipt schema 3 stay compatible; run `rexdeck enable <id>` after upgrading to refresh each applied integration.
- `rexdeck plugins` and aggregate `status` rows disclose each integration's tool, versions, license, context, capabilities and default layout. Document adding an interactive terminal tool and the limits for one-shot, data-backed and GUI programs.
